SLMS SIMULATION ALGORITHM (CURRENT INPUT/ CLOCK SEMANTICS)

1. Input nodes receive their scheduled values.
2. Evaluate operations are drained from the combinational queue.
3. The simulator commits nodes in topological order and continues draining
   combinational work until propagation is complete.
4. Sequential state-change operations are then drained.
5. A flip-flop's data/control inputs (D, J, K, or T) are updated immediately
   when their evaluate() method is called. A detected active clock edge queues
   only a ChangeStateOperation.
6. Because combinational propagation completes before the sequential queue is
   drained, a data/control input and active clock edge arriving in the same
   simulation time are sampled using the newest data/control value.

There is no SetPortOperation, no SET_PORT operation type, and no sequential
queue reordering or hold-time warning for same-time input/clock events.
